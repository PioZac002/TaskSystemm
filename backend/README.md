# TaskSystem API

REST API (Java 25, Spring Boot 4.1) for the TaskSystem web app. It implements the full `/api/v1/**` contract the frontend uses: JWT auth with refresh tokens, projects, issues, teams, comments, files, labels, notifications and activity history.

> Running the whole stack with Docker is described in the [root README](../README.md). This file covers the API on its own.

## Requirements

- JDK 25 or newer
- Nothing else: Maven comes with the wrapper (`./mvnw`)

## Run locally

```bash
./mvnw spring-boot:run
```

The API starts on **http://localhost:6901**, the port the frontend's `.env.example` points to.

| Profile | Database | Seeding | Used by |
|---|---|---|---|
| *(default)* | H2 file database in `./data` | admin + labels; demo workspace with `APP_DEMO_SEED=true` | local development |
| `docker` | PostgreSQL from `SPRING_DATASOURCE_*` | admin + labels + demo workspace (`APP_DEMO_SEED`, default `true`) | `docker-compose.yml` |
| `prod` | whatever you configure | none | production |

## API documentation

Swagger UI (springdoc-openapi) is served alongside the API:

- **Swagger UI:** http://localhost:6901/swagger-ui.html
- **OpenAPI 3.1 schema:** http://localhost:6901/v3/api-docs (add `.yaml` for YAML)

Both paths are public. They are available when the API is reached directly (the local run above);
the Docker stack proxies only `/api/` through nginx, so browse the docs from a local run or publish
the backend port in `docker-compose.yml`.

Endpoints are grouped by `@Tag` (Issues, Projects, Teams, ...); everything
except the Auth and System tags requires a bearer token, marked with a padlock.

To call a protected endpoint from the UI: `POST /api/v1/login`, copy `accessToken` from the response,
click **Authorize** and paste it (without `Bearer` — the prefix is added for you). The token is kept
across page reloads via `springdoc.swagger-ui.persist-authorization`.

## Database

- **Local:** H2 in file mode (`./data/tasksystem.mv.db`, ignored by git), so data survives restarts. Delete `./data` to reset.
  H2 console: http://localhost:6901/h2-console (JDBC URL `jdbc:h2:file:./data/tasksystem`, user `sa`, empty password).
- **PostgreSQL:** activate the `docker` profile and provide the connection:

  ```bash
  SPRING_PROFILES_ACTIVE=docker \
  SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/tasksystem \
  SPRING_DATASOURCE_USERNAME=tasksystem \
  SPRING_DATASOURCE_PASSWORD=secret \
  ./mvnw spring-boot:run
  ```

- The schema is generated by Hibernate (`ddl-auto: update`). Entities work unchanged on H2 and PostgreSQL; file contents use a plain binary column (`bytea` on PostgreSQL) instead of `@Lob`, which PostgreSQL would store as a large object.

## Configuration

| Property | Environment variable | Default |
|---|---|---|
| `server.port` | `SERVER_PORT` | `6901` |
| `app.security.jwt.secret` | `APP_SECURITY_JWT_SECRET` | development placeholder (min. 32 bytes in real use) |
| `app.cors.allowed-origins` | `APP_CORS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:4173,http://localhost:3000` |
| `app.demo.seed` | `APP_DEMO_SEED` | `false` (`true` in the `docker` profile) |
| `spring.datasource.*` | `SPRING_DATASOURCE_URL`, `_USERNAME`, `_PASSWORD` | H2 locally, PostgreSQL in `docker` |

## Architecture

Package by feature, controller → service → repository:

```
com.tasksystem.api
├── common/          config (security, JWT, CORS, seeders), error handling, CurrentUserService
├── auth/            /login, /register, /auth/regenerate-tokens (rotating refresh tokens)
├── user/            users and admin operations (password reset, role change)
├── project/         projects and issue statistics (progress, counts per status/priority)
├── issue/           issues, <SHORTNAME>-<n> keys, mutation endpoints, attachments
│   └── activity/    per-issue activity log (types match the UI)
├── team/            teams and membership
├── comment/         issue comments
├── file/            files stored in the database (comment and issue attachments)
├── masterdata/      dictionaries (e.g. issue labels), upsert with a delete flag
├── notification/    notifications (issue assigned, new comment)
└── system/          /api/v1/test/version
```

Conventions: DTOs as records, constructor injection (no Lombok), `jakarta.validation`, `@Transactional` on services, `open-in-view: false`.

## Security

- **Access token:** JWT HS256 (Spring OAuth2 Resource Server / Nimbus), 15 min TTL, claims `sub` (user id) and `roles` (`ROLE_USER` / `ROLE_ADMIN`).
- **Refresh token:** random, single-use (rotated on every refresh), stored in the database, 7 day TTL.
- `/api/v1/admin/**`, `PUT /api/v1/user/role` and `DELETE /api/v1/user/**` require ADMIN; login, register, refresh and `/api/v1/test/version` are public.

## Frontend compatibility notes

- The frontend sends payloads in both camelCase and PascalCase, so `accept-case-insensitive-properties` is enabled.
- `GET /api/v1/project/{id}` returns project statistics **plus** the project's issues.
- `PUT /api/v1/issue/update` is a **full** update: omitted fields (e.g. `dueDate`, `assigneeId`) are cleared. Partial updates use `/issue/update-status`, `/update-priority`, `/assign`, `/assign-team`, `/update-due-date`.
- Error responses carry the message under both `message` and `Message`.
- File upload: `POST /api/v1/file` with parts `File` + `CommentId`, and `POST /api/v1/issue/{id}/attachments` with part `file`.
- The SignalR hub (`/notificationHub`) of the earlier .NET backend is **not** implemented; notifications are fetched over REST (`/api/v1/notifications/me`). WebSocket/STOMP would be the Java-side option if real-time delivery is needed.
